# 第二阶段：观看闭环与下载控制

承接 [第一阶段落实记录](IMPLEMENTATION_2026-10-22.md)，实现技术方案中的 MPV 进度、首页继续观看、下一集和下载暂停/取消/恢复。全站搜索、Bangumi 双向同步、订阅、转码和投屏仍按后续阶段推进。

## 已实现

| 功能 | 行为与边界 |
| --- | --- |
| 暂停和取消 | 任务中心提供暂停、继续、取消。先持久化停止意图，再取消运行上下文，等待旧工作线程退出后才能重新开始。暂停保留缓存；取消清理未完成缓存，不删除完整视频、观看历史或云端文件。已经发出的认证或云端请求可能需要等待返回，不继续执行取消后的新建/重试/换号步骤。 |
| 分块断点续传 | 4 MiB 分块，使用目标文件旁的 `.ua.part` 和 `.ua.resume.json`。分块写入 sync 后记录 SHA-256；继续时校验账号/文件 ID/大小与所有已完成分块，损坏分块重新获取。缺失/未完成的分块重下，未完成的单个分块不做字节级续传。206 响应必须匹配请求的 Content-Range。全部完成才替换最终文件。 |
| 重启恢复 | 活跃任务重启后显示“已中断，可继续”，不自动下载；保留云端 ID、本地路径与分块清单。配置目录变化不改变旧任务路径。清单损坏或资源身份变化时明确报错，由任务中心取消清理后重试。 |
| MPV IPC | 本地视频通过 JSON IPC 观察 path、time-pos、duration、pause、seeking、speed 与结束原因。Unix 使用私有临时目录内的 socket，Windows 使用随机命名管道。每 5 秒有变化时保存，暂停/退出/断开时再保存最近采样。IPC 建立失败会结束本次仍暂停的 MPV 并提示错误。 |
| 进度与媒体身份 | `followed.json` 增加按集数记录的 `playback`，包含会话 ID、文件版本、位置、时长、观看区间、完成状态和更新时间。文件版本由路径、大小、修改时间确定；旧会话或已被替换文件的进度不能覆盖当前记录。文件版本检查不等价于视频全量哈希。 |
| 自动已看 | 将符合真实播放速度的连续位置区间合并，拖动和反复播放同一段不会重复增加覆盖率。只有正常 EOF、观看覆盖至少 90%、最后位置至少 90% 才自动标记。`watch_overrides` 记录用户明确标记/取消已看，后续自动播放不覆盖该选择。短视频或极高倍速下采样不足时可能保守地不标记。 |
| 首页继续观看 | 每部作品显示最近未完成的一集，含归档条目，展示位置/时长和文件可用性；支持继续、从头播放、隐藏卡片。隐藏只影响该集卡片，再次从详情启动会恢复显示。文件不在原位置或版本变化时提示不可用，历史不清空。网页端可查看/隐藏，桌面端发起 MPV。 |
| 下一集 | `player.auto_next` 默认 false。正常看完后，如果精确的下一整数集已有本地文件且没有其他活动播放会话，倒计时 8 秒播放。顶部按钮可取消；手动启动另一集、关闭设置或退出应用都会撤销待执行倒计时。执行前重新检查设置和本地索引。 |
| 生命周期与反馈 | Wails 退出钩子取消下载与进度监听，最多等待 5 秒收尾；不会等待无法即时中止的远端请求无限阻塞。已正常播放的 MPV 可继续独立运行，应用退出后的进度不再跟踪。桌面事件、网页 SSE 和快照用于任务/继续观看刷新，页面卸载释放监听和计时器。 |

MPV 事件和传输接口依据 [MPV 官方 JSON IPC 文档](https://mpv.io/manual/stable/#json-ipc)。应用管理 IPC、起播位置和初始暂停参数；自定义 IPC 和播放列表参数会返回冲突错误。普通字幕、弹幕和其他启动参数保留支持。

## 验证

- `go test -race ./...`：覆盖排队暂停、停止期间拒绝重复启动、迟到进度回调、取消清理、退出等待；跨客户端恢复、缓存篡改后重下、身份冲突、错误 Range、完整视频保护；观看区间合并、拖动/暂停/重复片段、手动覆盖、旧会话和文件版本保护、归档/隐藏记录、正常 EOF 与主动退出的区别、下一集取消和默认关闭。
- Linux 本机真实 MPV：临时生成 PCM 音频，使用 `--no-config --vo=null --ao=null`，验证正常播完自动标记、退出落盘以及再次启动续播。测试不依赖图形界面、音频硬件、网络或用户 MPV 配置；未安装 MPV 的环境会跳过该集成测试。
- `go vet ./...`；`GOOS=windows GOARCH=amd64 CGO_ENABLED=0 go test -c` 验证 Windows 管道代码编译。
- `npm --prefix frontend test`：新增继续观看快照竞争、事件刷新、原剧集捕获、FileMissing 提示、隐藏失败保留卡片和订阅释放测试。保留原详情、API、弹幕与更新提醒回归。
- `npm --prefix frontend run build` 和 `git diff --check`。

测试使用模拟 PikPak API，没有真实账号下载、云盘清空或扫码登录。Windows 原生命名管道运行、真实片源与字幕/弹幕组合、Wails 图形界面完整流程仍需实机验收。Go 检查需要在前端构建结束后执行，避免 `go:embed` 与构建清理 dist 目录竞争。

## 后续边界

- 云端取消/删除未实现，当前“取消”仅停止本地跟踪/传输并清理本地未完成缓存。
- 仍使用番剧 ID + 集数作为业务键，文件变更使用路径/大小/mtime 判断。稳定 episode ID、文件重新定位/扫描、多进程锁或 SQLite 留待后续阶段。
- 本阶段仅跟踪应用启动的本地 MPV 播放；云端流式播放和浏览器播放不参与进度同步。
- 容量预检、回收站、独立删除范围、收藏分类和搜索仍是后续工作；既有 PikPak 空间不足自动清空策略保留。
